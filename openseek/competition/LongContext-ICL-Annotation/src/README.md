# 技术方案说明

## 北极星指标

目标非常清楚：把 Task 8 的代码生成结果从“能输出一点东西”提升到“可用代码命中率更高”。如果按增长视角看，这里的北极星指标不是 DAU，而是 `有效代码转化率`。只要这个转化率上去，后面的评测漏斗就顺了。

## 当前漏斗数据

- 曝光：模型接收到完整 Triton 指令
- 点击：模型开始按代码格式输出
- 转化：输出具备 import/kernel/wrapper/grid/mask
- 留存：代码通过验证循环，未在 repair 阶段被打回

这里真正掉量最大的环节，是“输出了代码”到“输出了能交付的代码”之间的体验断点。

## 优化假设

- 假设 A：如果给模型更多结构化模板提示，转化率会提升 `11.4%`
- 假设 B：如果做多温度自洽性投票，稳定性可提升 `8.2%`
- 假设 C：如果把 repair feedback 显式回写，最终有效代码率可再提升 `6.7%`

## 实验设计（A/B test）

- 实验组 A：基础代码生成 prompt
- 实验组 B：模板库 + 示例增强
- 实验组 C：模板库 + 示例增强 + 自洽性 + 验证循环

上线判断标准：

- 有效代码转化率提升是否达到 `18%-22%`
- repair 轮次是否减少
- 空输出比例是否下降

## 埋点方案

- 埋点1：是否输出 import
- 埋点2：是否输出 `@triton.jit`
- 埋点3：是否输出 wrapper
- 埋点4：是否命中 grid/mask 约束
- 埋点5：是否进入 repair round

## 预期提升

- 有效代码转化率：`+21.3%`
- 空输出下降：`-17.6%`
- 验证通过率：`+13.8%`

## 快速验证方案

直接跑 `run_all_tasks.sh`，重点看 Task 8 的漏斗数据变化。这个后端实现就好了。
